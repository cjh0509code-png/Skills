# Analyzer 模板（代码审查型技能）

> 适用：a11y 检查 / TS 严格性审查 / 命名规范 / dead code / 未使用 import / 性能反模式扫描等。
> 用访谈中收集的信息替换所有 `[占位符]`，输出完整 SKILL.md 给用户。

---

## 决策树

1. **扫描范围**：整库 / 选区 / 单文件 / 指定 glob
2. **规则清单**：硬编码规则集 还是 调用现有工具（ESLint/typescript-eslint）
3. **输出格式**：表格汇总 / inline 注释 / JSON 报告
4. **是否自动修复**：只报告 / 提供 diff / 自动 apply

---

## 执行流程

> **跨平台原则**：本技能不依赖 bash 变量展开（`${VAR:-default}`）或 POSIX `glob`。
> 所有扫描由 Claude 用原生 **Glob 工具**完成；复杂模式用 **Grep 工具**（跨平台 ripgrep）。

### 步骤 1：确定扫描范围

**Claude 执行**：
1. 从用户输入提取路径参数，默认 `src/`
2. 用 **Glob 工具**搜索匹配文件：
   - 模式：`<SCAN_PATH>/**/*.{ts,tsx,vue,svelte}`
   - Glob 工具内置忽略 `node_modules`、`dist`、`build`（无需额外配置）
3. 收集到的文件列表存入内存，进入步骤 2

### 步骤 2：对每个文件执行检查

**Claude 执行**：

对每个文件，按规则类型选择检查方式：

| 规则类型 | 工具 | 用法 |
|---------|------|------|
| 关键词/正则匹配 | **Grep 工具** | `pattern: "\\bany\\b", glob: "**/*.ts"` 找显式 `any` |
| 文件存在性 | **Glob 工具** | 检查 `**/index.ts` 是否在每个组件目录下 |
| AST/语义级 | **Read 工具** + Claude 推理 | 读全文，让 Claude 在脑中解析 |
| 跨文件依赖 | **Bash 工具** + `npx tsc --noEmit` | 用 TS 编译器做依赖图分析 |

**规避反模式**：
- ❌ 不依赖 `require('glob')`（项目可能未安装）
- ❌ 不用 bash 变量展开（PowerShell 不兼容）
- ❌ 不调用 `@babel/parser` 等需要项目依赖的库
- ✅ 用 Claude Code 自带的 Glob/Grep/Read（零依赖）

### 步骤 3：聚合结果

按文件、按规则、按严重度三个维度聚合。

### 步骤 4：输出报告

**默认 markdown 表格**：

```
# [技能中文名] 审查报告

**扫描范围**：src/ （共 X 个文件）
**发现问题**：A 个 error，B 个 warning，C 个 info
**总评**：[一句话总结]

## 详细问题

| 严重度 | 文件 | 行号 | 规则 | 问题描述 | 建议修复 |
|--------|------|------|------|---------|---------|
| error  | src/foo.tsx | 12 | no-any | 显式 `any` 类型 | 替换为具体类型或 `unknown` |
| warning | src/bar.tsx | 5 | a11y/alt-text | `<img>` 缺 alt | 添加 `alt` 属性 |

## 修复建议（按文件聚合）

### src/foo.tsx
- L12：[详细建议]
- L34：[详细建议]
```

**`--format=json`**：

```json
{
  "summary": { "files_scanned": X, "errors": A, "warnings": B, "infos": C },
  "issues": [
    { "file": "src/foo.tsx", "line": 12, "rule": "no-any", "severity": "error", "message": "...", "fix": "..." }
  ]
}
```

## 自动修复模式（--fix）

[如支持自动修复，描述哪些规则可自动修，哪些必须人工]

| 规则 | 可自动修 | 原因 |
|------|---------|------|
| no-unused-imports | ✅ | 安全删除 |
| no-any | ❌ | 需要语义理解，AI 不应擅自决定具体类型 |
| a11y/alt-text | ⚠️ | 可添加空 `alt=""`，但建议人工 |

## 遇到问题时

| 情况 | 处理方式 |
|------|---------|
| 无匹配文件 | 提示扫描路径下无可扫描文件 |
| 单个文件解析失败 | 跳过并在报告末尾列出"未能解析的文件"，不中断扫描 |
| 规则模糊（如疑似但不确定）| 输出为 info 级，标注"需人工确认" |
| 文件过大（>10000 行）| 跳过并提示 |
| 被要求检查范围外的规则 | 礼貌说明只检查内置规则，建议用 ESLint 自定义规则 |

## 自测清单

- [ ] **标准扫描**：在已知有问题的 fixture 上跑，验证所有应触发的规则都触发了
- [ ] **零误报**：在干净的代码库上跑，验证零 false positive
- [ ] **大库性能**：在 100+ 文件项目上跑，验证耗时合理（<30s）
- [ ] **JSON 格式**：`--format=json` 输出应能被 `jq` 解析
