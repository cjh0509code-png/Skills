## 执行流程

> **跨平台原则**：本技能不依赖 bash heredoc、`diff`、`head`、`cp`、`$VAR` 展开等 POSIX 特有命令。
> 所有逻辑由 Claude 用原生工具（Glob / Read / Write / Edit）执行；只在调用 `npx tsc` / `npx vitest` 这类跨平台 CLI 时才用 Bash 工具。

### 步骤 1：解析目标文件列表

**Claude 执行**：
1. 从用户输入提取路径或 glob 模式
2. 用 **Glob 工具**搜索匹配文件，自动排除 `**/node_modules/**`、`**/dist/**`、`**/build/**`
3. 若无匹配 → 立刻告知用户并停止

### 步骤 2：对每个文件生成转换后版本

**Claude 执行**：
1. 用 **Read 工具**逐个读取源文件
2. 在内存中应用转换规则（见上方"转换规则"章节）：
   - 简单替换：用字符串/正则操作
   - AST 级转换：在脑中描述转换，必要时 instruct 用户跑 `jscodeshift` / `ast-grep` 子命令
3. 把转换结果暂存为变量或临时文件
   - 临时文件路径：`${WORKSPACE}/[技能名]/transformed/<相对路径>`（WORKSPACE 决议见主 SKILL.md）

### 步骤 3：生成 diff 预览

**Claude 执行**：
1. 在对话内**直接展示** Before/After 对照（不依赖 `diff -u`）
2. 用 Markdown 代码块呈现：

```
📝 [技能中文名] 转换预览：src/foo.tsx

——— Before ———
[源代码前 30 行]

——— After ———
[转换后前 30 行]

——— 变更摘要 ———
• 第 X 行：[改了什么]
• 第 Y 行：[改了什么]

应用此转换？（--apply 跳过此确认）
```

### 步骤 4：用户确认后应用

**Claude 执行**：
1. 用 **Read 工具**先读源文件全文
2. 用 **Write 工具**把原文件**先备份**到 `<原路径>.bak`（不靠 `cp`）
3. 用 **Write 工具**把转换结果覆盖原路径

### 步骤 5：转换后验证（跨平台）

**用 Bash 工具调用跨平台 CLI**：

```bash
npx tsc --noEmit
```

如果是单文件 tsc，由于 tsc 对单文件检查有限制，更稳的做法是把临时 tsconfig 用 `node -e` 写到 `os.tmpdir()`（详见 `references/frontend-validators.md` §3.2），然后：

```bash
npx tsc --noEmit -p <临时tsconfig路径>
```

测试：

```bash
npx vitest run --related <转换后的文件相对路径>
```

**Claude 解析结果**：检查 exit code 和 stdout，若失败则在最终报告里标注"⚠️ 类型检查未通过"或"⚠️ 相关测试未通过"，但**不回滚**（保留 .bak 让用户决定）。

### 步骤 6：输出总结

```
✅ 转换完成
  • 已转换：3 个文件
  • 跳过：1 个文件（含不可转换模式，详情见下）
  • 类型检查：通过
  • 相关测试：通过

跳过的文件：
  - src/legacy/Foo.tsx：行 23 使用了 [不支持的模式]，需人工迁移

已备份原文件至 *.bak（如需回滚：
  • Unix / macOS / Git Bash:  mv X.bak X
  • Windows PowerShell:        Move-Item X.bak X -Force
  • Windows cmd:               move /Y X.bak X
  • 或用编辑器手动重命名）
```

## 严格遵守的约束

- **不静默删除代码**：哪怕觉得是 dead code，也保留 + 标注
- **保留注释**：源代码的注释要原样迁移到目标位置
- **保留格式**：缩进、空行、import 顺序尽量不动
- **不引入新依赖**：除非用户明确允许
- **不可转换时报告，不硬转**：宁可标注 `// TODO: manual migration needed` 也不输出错的代码

---

## 遇到问题时

| 情况 | 处理方式 |
|------|---------|
| 文件不存在 | 报错并退出 |
| 文件含语法错误 | 报错指出 parser 失败位置，建议先修语法 |
| 文件部分无法识别 | 转换可识别部分，不可识别部分加 `// TODO` 注释保留原样 |
| 批量转换中某文件失败 | 跳过该文件，继续后续，最后汇总失败列表 |
| 类型检查失败 | 不回滚，提示用户检查，给出最可能的原因 |
| 被要求转换非目标 pattern | 礼貌说明只处理 [源 pattern]，建议合适工具 |
